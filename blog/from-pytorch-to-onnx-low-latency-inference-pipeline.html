From PyTorch to ONNX: Designing a Low-Latency Model Inference Pipeline

PyTorch ONNX Runtime Inference Pipeline FastAPI Model Deployment

Training deep learning models in PyTorch provides maximum flexibility for research, rapid experimentation, and gradient exploration. However, deploying raw PyTorch models into low-latency production backend services introduces unnecessary overhead: heavy GPU dependency, large Python runtime footprints, and sluggish single-sample inference latency.

To serve neural models efficiently inside backend microservices, modern ML engineering decouples model training from production inference.

In this case study, I walk through the architecture of converting PyTorch models into ONNX (Open Neural Network Exchange) format and serving them using ONNX Runtime inside FastAPI microservices.

2. Exporting PyTorch to ONNX

Exporting a PyTorch model requires tracing sample input tensors through the neural computational graph to generate a standardized graph format: 

import torch
import onnxruntime as ort
import numpy as np

def export_model_to_onnx(model: torch.nn.Module, input_shape: tuple, export_path: str):
    model.eval()
    dummy_input = torch.randn(*input_shape)
    
    # Export to static ONNX graph
    torch.onnx.export(
        model,
        dummy_input,
        export_path,
        export_params=True,
        opset_version=14,
        do_constant_folding=True,
        input_names=["input"],
        output_names=["output"],
        dynamic_axes={"input": {0: "batch_size"}, "output": {0: "batch_size"}}
    )
    print(f"Model exported successfully to {export_path}")

3. Verifying Numerical Parity

Before deploying an exported ONNX model, we verify that ONNX Runtime inference outputs match PyTorch outputs within a strict numerical tolerance (`np.testing.assert_allclose`): 

def verify_parity(torch_model, onnx_path, input_data: np.ndarray):
    # PyTorch Inference
    torch_model.eval()
    with torch.no_grad():
        torch_out = torch_model(torch.from_numpy(input_data)).numpy()
        
    # ONNX Runtime Inference
    ort_session = ort.InferenceSession(onnx_path, providers=["CPUExecutionProvider"])
    ort_inputs = {ort_session.get_inputs()[0].name: input_data}
    ort_out = ort_session.run(None, ort_inputs)[0]
    
    # Check numeric parity
    np.testing.assert_allclose(torch_out, ort_out, rtol=1e-03, atol=1e-05)
    print("Numerical parity check passed!")

4. Pre-Warmed ONNX Runtime Service

In a backend FastAPI microservice, ONNX sessions are loaded during application startup. Running a "warmup" inference query initializes internal memory pools and execution graphs before live traffic arrives: 

from fastapi import FastAPI
import onnxruntime as ort
import numpy as np

app = FastAPI()
session = None

@app.on_event("startup")
async def load_onnx_model():
    global session
    session = ort.InferenceSession("model.onnx", providers=["CPUExecutionProvider"])
    
    # Session Warmup
    dummy = np.zeros((1, 30, 10), dtype=np.float32)
    session.run(None, {session.get_inputs()[0].name: dummy})
    print("ONNX Session loaded and warmed up.")
