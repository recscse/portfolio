Building a Production-Ready OAuth2 Automation SDK for Upstox

Python OAuth2 Playwright SDK Architecture PyPI
Disclaimer: upstox-auth-pro is an independent open-source developer tool published on PyPI. It is not affiliated with, endorsed by, or official software of Upstox or RKSV Securities India Pvt. Ltd. Never log credentials or commit secrets to public version control.

Automated trading infrastructure requires seamless, unattended authentication before the Indian stock market opens at 9:15 AM IST. However, Indian brokerage APIs like Upstox enforce daily access token expiration and mandatory 2FA authentication flows. Manually launching a browser every morning to log in and update access tokens destroys the operational autonomy of algorithmic systems.

To solve this problem cleanly and reliably, I architected and published Upstox Auth Pro, an open-source Python SDK designed to automate the OAuth2 login flow, calculate Time-Based One-Time Passwords (TOTP), handle secure token persistence, and recover gracefully from network glitches.

1. The Operational Challenge

Standard OAuth2 authorization code flows are built with human interactions in mind:

  1. The user is redirected to a browser login page.
  2. The user enters mobile number/user ID, password/PIN, and dynamic OTP.
  3. The authorization server redirects back to a redirect_uri with a temporary code.
  4. The client application exchanges the authorization code for an access_token via a POST request.

In an automated trading context, requiring manual daily browser logins introduces single points of failure. If the login process fails or stalls due to network timeouts, scheduled algorithmic jobs miss the morning market opening.

2. SDK Architecture & Components

The SDK is structured into decoupled modules to ensure high maintainability and flexibility:

  • UpstoxAuthenticator: Core orchestration class for handling authentication state.
  • BrowserAutomator: Playwright wrapper that handles headless UI interaction, input filling, DOM wait events, and screenshot diagnostics.
  • TOTPManager: Crypto helper leveraging pyotp to generate 6-digit 2FA tokens on the fly from a base32 secret key.
  • TokenStorageManager: Pluggable storage abstraction (supporting JSON file storage, environment variables, or custom adapters).
  • CLI Entrypoint: Standalone command-line interface (upstox-auth) for cron jobs and continuous integration pipelines.

2FA / TOTP Generation

To complete the 2FA prompt automatically, the system uses the user's registered TOTP secret key. Generating the current valid OTP code in Python requires high clock synchronization accuracy: 

import pyotp
import time

class TOTPManager:
    def __init__(self, totp_secret: str):
        self.totp = pyotp.TOTP(totp_secret)
        
    def generate_code(5):
        """Generates current 6-digit TOTP token."""
        return self.totp.now()

    def seconds_remaining(self):
        """Returns time remaining before current TOTP expires."""
        return 30 - (int(time.time()) % 30)

3. Headless Browser Automation with Playwright

Playwright was chosen over Selenium due to its modern async event model, robust auto-waiting capabilities, and isolated context isolation. Selenium often suffers from race conditions when dynamic UI elements shift during DOM rendering.

The login flow performs the following automated DOM steps:

  1. Navigates to the official Upstox OAuth URL constructed with client_id and redirect_uri.
  2. Waits for the mobile number input selector and types credentials using human-like delays.
  3. Submits the form and awaits the 2FA input box.
  4. Calculates the current TOTP via pyotp. If the remaining window is under 3 seconds, it waits for the next TOTP cycle to prevent authorization rejection during transit.
  5. Types the 6-digit TOTP and 6-digit PIN into respective input fields.
  6. Intercepts the final HTTP 302 Redirect to extract the authorization code query parameter directly from the browser response header before rendering finishes.
# Direct code extraction via URL interception
async def extract_auth_code(page, redirect_uri: str) -> str:
    async with page.expect_navigation(url=lambda u: redirect_uri in u, timeout=20000):
        await page.click("#submit-btn")
    
    current_url = page.url
    parsed_url = urllib.parse.urlparse(current_url)
    query_params = urllib.parse.parse_qs(parsed_url.query)
    
    if "code" not in query_params:
        raise AuthenticationError(f"Authorization code missing in URL: {current_url}")
        
    return query_params["code"][0]

4. Token Storage Abstraction & Timezone Awareness

Upstox access tokens are valid until 3:30 AM IST of the following day. To avoid making redundant headless login calls during restarts or strategy executions throughout the day, the SDK checks existing tokens against an IST timezone threshold before initiating a browser session.

Token metadata is persisted along with explicit expiration timestamps formatted in ISO-8601 with Asia/Kolkata timezone offset:

5. Error Handling, Retry Strategy, & Screenshots

Production automation must survive unexpected UI layout updates, network latency spikes, and cloud deployment cold-starts.

To guarantee operational reliability:

  • Exponential Backoff: Retries browser interaction up to 3 times with exponential delays (2s, 4s, 8s).
  • Diagnostic Screenshots: On any uncaught selector exception or navigation timeout, the SDK captures a PNG screenshot saved with a timestamp identifier (e.g., auth_failure_20260215_083012.png) to aid root-cause analysis.
  • Stealth Mode Options: Masks browser automation flags (navigator.webdriver) to avoid false-positive bot protection blocks during legitimate login sequences.

7. Key Tradeoffs & Technical Lessons

  1. Headless Browser vs Native HTTP Requests: Upstox authorization pages utilize heavy dynamic client-side JS. Simulating raw HTTP POST requests to login endpoints breaks whenever UI anti-CSRF tokens update. Using Playwright provides maximum resilience against frontend DOM changes at the cost of a slightly larger memory footprint during initial login (~150MB for Chromium).
  2. Token Caching Isolation: Decoupling the storage mechanism using interface classes allows downstream applications to store tokens in Redis, AWS Secrets Manager, or local encrypted disk stores without altering authentication logic.
